## 1. 发射门限与客户端随机流

实际 D2Client 导弹 CltDo50 位于 RVA `0x95110`；回调表 `0xF1260` 的50号槽指向此处。周期取 CltParam1，零值则计算技能 calc4，本级为2；半径取 CltParam2或技能 aurarangecalc，本级为12。CltParam3=2、CltParam4=128，判断为：

`elapsed > 2 && elapsed < 128 && elapsed % 2 == 0`

因此本配置在年龄4、6、8……126共尝试62次。不是把采样数量62硬编码成常数，其他配置由表和公式求门限。

注意 D2Common#11125 的源码名 `MISSILE_GetRemainingFrames` 容易误导：本版本 RVA `0x7A160` 实际返回 TotalFrames减CurrentFrame，即已过年龄；#11124返回倒计时。误读会反转整个门限。

每次喷发用控制器 missileData TargetX 重新 InitLowSeed，高半种子复位666，抽取两个[-12,12]偏移，再写回最终低半种子供下一次使用。两偏移均零时构造器改用(1,1)。生产实现只维护 transient 展示随机流，不消费战斗随机流。诊断回放可显式注入记录的初始 TargetX；这只是条件回放，不声称全局分配器随机流已复现。

全局 game_frame和各导弹倒计时的读取不是原子快照，部分倒推出生年龄比偶数门限晚1 tick。fixture 保留 `emission_age_estimate` 原值；测试只允许它与前一个偶数门限配对，再严格核对独立随机流、寿命、速度及所有坐标。没有把估算年龄冒充为精确回调时刻。生产相对出生间隔为2 tick；headless生产管线相位使记录出生tick为5、7……127，输入从SkillDo开始，不能把它当完整人物输入链的绝对延迟。

## 2. 地面移动与显示高度分离

客户端构造标志0x521，经 RVA `0x9EBE0`。飞石行 Vel14，原生速度为 `(14<<8)*75/100 = 2688`，按原生方向查表得到每tick fp16速度。

距离为 `max(abs(dx),abs(dy)) + min(abs(dx),abs(dy))/2`，寿命为 `max(1,(max(1,distance)<<16)/(16*2688))`。该批寿命含1..27内多种值。出生坐标为 `(cell<<16)+32768`，每tick累加原生速度；主机坐标投影减去半格。飞石到期不强行吸附到目标格。

图形高度在另一条路径中计算：RVA `0xC0080`初始化，`0xBFE00`更新，`0xBBA40`取辅助指针；gfx+0x30指向的辅助结构中，z位于+0xC、vz位于+0x18、加速度位于+0x24。初始高度 `z0=30<<11`，加速度-4096，初速度为 `(-z0-a*T*T/2)/T`，有符号除法向零截断。每次先z+=v，再v+=a。

**构造时先更新一次**，因此导弹年龄a对应a+1次高度更新，显示像素偏移为z>>11。之前固定50像素高度加线性落下不符合原版。地面位置用于排序和场景查询，高度仅用于绘制偏移。

## 3. 飞石与落地选帧

真实飞石DCC为15帧，表AnimLen也为15。CltDo1用倒计时控制起帧，等效游标为 `max(0,age-max(0,life-AnimLen-1))`，再对实际DCC帧数取模。较长飞行先保持第0帧，到最后游标15时实际DCC又选第0帧。不能使用帧数作门限后直接钳制末帧，也不能照搬熔岩巨球碎石的规则。

`NativeVolcanoPresentation`现在单独处理门限、目标距离飞行、高度和飞石帧；爆炸、地面岩浆通过 `NativeDruidSurfacePresentation`按各自18tick寿命正常推进。绘制资源冷加载不暂停位置、年龄和清理；资源到达时使用当前年龄。

## 4. 落地必须区分回调、创建与采样

CltHit55位于RVA `0x99150`，表 `0xF13D0` 的55号槽指向此处。有效owner存在时，分别尝试配置的两个子行：482爆炸、483地面岩浆，各18tick。没有发现概率省略某层的分支。

新增后台命中探针记录：

- 58次owner返回，均在飞石倒计时0，owner有效。
- 116次创建返回全部非零：58爆炸、58岩浆。
- 岩浆单位280、329已成功创建，但后续周期快照没有采到，导致快照统计仅56个岩浆。**数量不同不能直接推断某层随机不创建。**
- 已观察飞石327、330、350、405在倒计时归零前消失，未进入该命中回调；最后位置均靠近本次场景左侧。具体提前移除分支仍未知，不能称为已经证实的地形碰撞。

生产到期时先计算最终地面位置；owner已移除则不创建落地子层。飞石从已知主机场景进入无场景区域时直接清理，不模拟命中，包括最后一步才离开场景。该主机检查是有界保护，不等同原版全部Room/阻挡规则。空地图诊断没有这些移除条件，因此62次飞行均创建爆炸和岩浆，不能要求与真实场景的58次回调或快照数量相等。

探针位于owner返回0x991A4、两次创建返回0x991EE/0x99207，以及独立结束位置0x99220重新布置下一次观察；避免在同EIP立即重置导致自陷循环。新增 `d2game_druid_volcano_hits` 已加入x86构建清单。
