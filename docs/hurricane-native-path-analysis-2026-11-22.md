# 飓风：原生离散轨迹、八方向与成批生成

本轮将 Hurricane(250) 的客户端连续圆周近似替换为 1.10f 的离散路径。复用此前后台批次 `20261122-014022-d9d92f67`，没有启动新的原版游戏、没有前台操作或 UAC。德鲁伊目前 **9/30 有运行采集、9/30 有限定比较**，仍不代表完整技能、战斗或像素一致。

## 找到的缺失步骤与修复

原版技能 CltActive90 每帧调用构造器九次，各次选择八个出生偏移之一、三个资源之一，并在创建成功后从 [0,75) 取整数高度。过去每 1/225 秒创建一个连续圆周粒子，虽然平均频率相同，但同一逻辑帧的九个粒子被人为分散了出生年龄。

现在按 25Hz 成批生成九个，支持 60Hz 渲染和较长渲染间隔的补进。三个资源和 225 个/秒的平均频率保持不变。随机选择改用原生 Seed 的 mask/modulo 策略，使用独立客户端展示流，状态再次激活时延续随机流。没有对齐原版施法者的完整 RNG 消费序列；不能据此声称同一次施放会生成逐个相同的碎片。

原版 CltDo60（D2Client RVA `0x9D380`）每两个已过帧重算切向目标。设当前整数坐标为 (ix,iy)、出生中心为 (cx,cy)，新目标是：

```
tx = ix + iy - cy
ty = iy - ix + cx
```

由当前 fp16 坐标朝该目标格中心计算方向，再按原生向量查表及速度系数推进。速度是 `(Vel<<8)*75/100`，不使用浮点单位向量或固定角速度。出生位置为格中心，初始切向偏移为 `(laneY,-laneX)`。每个碎片保留自己的出生中心；角色移动后只改变新碎片的中心。

新增 `NativeHurricanePresentation.Flight` 复用已有 `D2PathStep.directionVector`，保存 fp16 位置、速度、方向及离散年龄。真实 `ReferenceElementalPresentationSystem` 使用同一个构造/更新路径；旧三角函数圆周实现及其半径/角速度字段已移除。图形高度仅影响绘制偏移，排序位置保留原生地面路径。

风带有八个 DCC 方向，D2CMP 的映射并不是直接把 64 方向等分后编号：查表使用 `[4,0,5,1,6,2,7,3][((facing+4)&63)>>3]`。现在使用固定版本实际查表，rock/tree 仍为单方向。动画按整数年龄推进，swoosh 每帧增加 128，rock/tree 增加 256；寿命为 22/20 帧，避免浮点年龄在换帧边界落后一帧。资源晚到时直接显示当前路径、方向和动画帧。

## 原版依据与观察限制

原始 `worker/250/missiles.jsonl` 共 49,640 条记录、3869 个单位，覆盖全部八个出生偏移和三种资源。3844 个单位直接观察到年龄0，25个首次观察为年龄1；后者以已观察到的首步速度反推出生点，已在 fixture 标记为推导输入。所有接受样本的中心字段保持不变。

以动画光标应等于 `age*rate` 的独立条件识别出26条不一致记录：它们的光标对应前一帧，少数位置/速度也处于相邻更新阶段。记录保存在 `rejected_samples`，原始 JSONL 不变。这符合非原子读取的情况，但没有将这些记录修正或作为匹配证据。

其余 **49,614 条样本**的 fp16 位置、速度、64方向、高度均与生产路径模型精确相同，动画光标/速率也已核对。方向显示由静态 D2CMP 查表推导；没有新的实际 DCC 提交调用、GPU 图像或调用堆栈采集。

固定 DLL 的 SHA256、中心 getter #11141/#11143（导弹数据 +28/+2C）、目标 setter #10170、路径重算 #10142 和 D2CMP 八方向表在 `inspect_hurricane_path.py` 中校验，输出为 `tools/original-observer/hurricane-path-static-1.10f-2026-11-22.txt`。技能构造和 CltDo60 的既有反汇编仍见 `druid-storm-static-1.10f-2026-11-22.txt`。使用本地 Capstone/Win32 留存数据，不称为 REA Evidence。

## 生产回放与回归

`HurricaneOriginalParityTest` 比较所有接受样本，并选取八偏移×三资源的24个代表单位，直接通过真实展示系统构造、更新、选帧和选方向。它们共保留324个可用原版状态；立即加载和第10帧才加载两种生产场景分别比较这些状态，并验证生产的寿命上限。

不能把这24条称为全部完整原版寿命：部分偏移在本批地图边缘附近，只观察到年龄0或1。测试继续推进到20/22帧是本地寿命上限回归，不是证明原版也在地图边缘保留到该帧。

`HurricanePresentationLifecycleTest` 验证60Hz下每个逻辑帧九个、同批出生年龄相同、较长渲染间隔按整批补进、移动仅影响新中心、状态结束停止生成并允许已有碎片收尾，以及再次激活不重播初始随机流。伤害载体没有由这些客户端粒子替代。

最终主回归 **46 项通过**；之后的边界增量回归运行了 38 项相关测试并新增 1 项边界测试，全部通过。日志、XML及数据/代码哈希见 `tools/original-observer/hurricane-path-validation-2026-11-22.json`。

首轮37项中3项失败：两项将24条代表路径的样本数估成大于400，实际324条，逐字段断言当时已通过；一项旧回归用浮点 `.age*12.5` 作为风带帧号，恰好重现旧时钟落后一帧，已改为原版整数年龄依据。首轮日志保留，没有作为最终通过证据。
