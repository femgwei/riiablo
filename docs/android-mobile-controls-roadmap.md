# Android 移动端现状与触控改造路线

> 状态：方案记录，后续实现依据。本文只描述输入、目标选择、拾取和 UI 层改造，
> 不改变 Diablo II 的伤害、抗性、怪物 AI、装备规则或存档格式。

## 1. 当前 Android 架构

Android 启动器使用 `Client(home, 360)`，移动端基础视口高度为 360。进入实际游戏后仍然
使用通用 `GameScreen`，地图、战斗、技能和网络逻辑与桌面版共用。Android 专用内容是在
游戏 HUD 上叠加触控控件，而不是完全独立的 Android 游戏场景。

主要代码：

- `android/src/main/java/com/riiablo/AndroidLauncher.java`
- `core/src/main/java/com/riiablo/screen/GameScreen.java`
- `core/src/main/java/com/riiablo/screen/panel/MobileControls.java`
- `core/src/main/java/com/riiablo/screen/panel/MobilePanel.java`
- `core/src/main/java/com/riiablo/screen/panel/SpellsQuickPanel.java`
- `core/src/main/java/com/riiablo/engine/client/AutoInteracter.java`

当前移动端 HUD 包含：

- 左下角虚拟摇杆，当前尺寸为 `164x164`；
- 底部移动菜单：角色、队伍、任务、切换武器、背包、技能、消息和退出；
- 右侧交互按钮；
- 右侧五个 `64x64` 技能按钮；
- 角色、背包、技能树、任务和商店等窗口继续复用已有面板；
- 移动端启用 `AutoInteracter`，自动寻找附近可交互对象。

当前不是完整的独立移动版 UI。移动菜单中的地图按钮尚未接入，虚拟摇杆背景也仍是
简化实现，部分面板布局仍按桌面版尺寸设计。

## 2. 当前技能操作

当前设计接近“技能快捷栏 + 长按选择”：

1. 短按右侧技能按钮，释放该按钮当前技能；
2. 长按约 0.5 秒，打开技能选择面板；
3. 选择技能后复制到被长按的技能槽；
4. 技能释放最终仍进入本地 `Actioneer` 或网络 `NetworkedActionSender`；
5. 交互按钮通过 `AutoInteracter` 选择最近的可交互目标。

当前移动端技能释放目标主要使用角色面向方向，部分调用仍以方向向量和无目标实体发送：

```text
技能按钮 -> 角色面向方向 -> Actioneer.cast(...)
```

这避免了触摸目标遮挡视野，但还没有完整的目标锁定、目标优先级和地面技能瞄准策略。

## 3. 改造原则

参考 D2R 手柄模式，但只移植输入和 UI 层的优点：

- 桌面端继续使用鼠标点击、路径寻路和左右键技能；
- Android 使用摇杆直接移动，不把屏幕点击当成长距离鼠标寻路；
- 技能、伤害、抗性、FCR、怪物 AI 和装备机制保持原版；
- 客户端只负责目标候选和输入表现，最终技能合法性由服务端/权威战斗逻辑验证；
- 精确瞄准作为可选操作，不强迫所有技能使用触摸点。

## 4. 后续改造优先级

### P0：移动移动和技能可用性

#### 4.1 Android 直接摇杆移动

- Android 下摇杆直接驱动角色速度和方向；
- 摇杆轻推走路，推到底奔跑；
- 继续使用现有精力/耐力系统；
- 保留桌面端鼠标路径寻路；
- 移动端世界点击主要用于选中、交互或辅助瞄准。

#### 4.2 软锁定和自动瞄准

新增统一目标选择器，技能按钮不再要求精确点选怪物：

```text
面向方向扇区内目标
> 摇杆方向上的目标
> 屏幕中心附近目标
> 距离最近的合法目标
```

建议按技能类型选择目标：

- 近战：面前最近敌人；
- 单体远程：方向扇区内最接近目标；
- 穿透/投射物：向锁定目标方向发射；
- 范围技能：选择敌群中心；
- 自身增益、召唤、传送：直接施法；
- 必须指定地面的技能：保留拖动瞄准模式。

目标失效、死亡、超出射程或不可见时，自动重新选择目标。目标指示器应保持小型，避免
像触摸光标一样遮挡画面。

#### 4.3 6+6 技能托盘

不建议在 360 高度的手机屏幕上同时显示 12 个按钮。建议采用两层技能页：

- 第一层显示 6 个技能；
- 长按或横向滑动切换第二层；
- 第二层再显示 6 个技能；
- 当前技能按钮显示冷却、法力、弹药和城镇限制状态。

操作建议：

```text
短按技能按钮       直接施法
长按技能按钮       打开该槽技能选择
滑动技能托盘       切换技能页
按住并拖动         临时精确瞄准
```

### P1：交互和拾取

#### 4.4 统一交互按钮

将开门、开箱、捡物品、NPC 对话、传送点、神殿和地下入口统一到交互按钮。目标优先级为：

```text
当前锁定目标
> 面向方向最近目标
> 距离最近可交互对象
```

#### 4.5 移动端拾取

- 近距离自动显示物品名称；
- 新掉落物短暂显示名称；
- 交互按钮一次拾取当前选中的一件物品；
- 金币进入拾取范围后自动拾取；
- 长按交互按钮显示附近物品列表；
- 不默认一次拾取附近全部装备。

#### 4.6 背包和腰带便利操作

- 增加背包自动整理；
- 增加从背包自动填充腰带；
- 药水使用仍遵守“先腰带、再背包”的现有规则；
- 背包、箱子和商店增加移动端导航焦点，不依赖精确鼠标坐标；
- 物品摆放和存档格式保持原版规则。

### P2：移动端 UI 和反馈

- 恢复并绘制虚拟摇杆背景；
- 接入移动端地图按钮；
- 技能托盘与底部菜单互斥或自动缩小，避免遮挡；
- 面板打开时自动调整技能按钮和交互按钮位置；
- 加大触摸命中区域，但不放大原始图标；
- 增加技能释放失败和目标切换提示；
- 技能释放、受击、拾取和爆炸增加 Android 震动反馈；
- 后续可将输入抽象为 `MouseInput`、`TouchInput` 和 `GamepadInput`，支持 PC 手柄与键鼠自动切换。

## 5. 建议的实现边界

优先新增一个独立的移动端输入/目标层，不让 `MobileControls` 直接决定所有战斗细节：

```text
Touch/Gamepad Input
        |
        v
MobileTargetSelector
        |
        v
SkillCastRequest
        |
        v
Actioneer / NetworkedActionSender
        |
        v
Server-authoritative validation
```

这样可以复用现有技能系统，也能保证单机和多人游戏使用同一套技能合法性检查，避免移动端
为了方便操作而绕过城镇限制、法力、弹药、射程或目标验证。

## 6. 当前结论

Android 已经有可运行的移动 HUD、虚拟摇杆、交互按钮和技能选择框架，但还属于“桌面游戏
逻辑 + 移动控制覆盖层”。下一阶段最值得优先完成的是：

1. 摇杆直接移动；
2. 软锁定和自动瞄准；
3. 6+6 技能托盘；
4. 统一交互按钮；
5. 附近物品选择和自动拾取金币。

以上完成后，再处理移动端背包、腰带、震动和 PC 手柄自动切换。
