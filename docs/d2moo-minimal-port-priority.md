# D2MOO (1.10f) → Riiablo Java 最小移植优先级清单

本文件保留项目的原始优先级要求，作为跨本地/远程访问的稳定入口。执行记录和每次
提交的测试结果仍写入 [`d2moo-progress-roadmap.md`](d2moo-progress-roadmap.md)。

## 前提和原则

- A1 地图 DS1 加载、角色渲染和移动已可用。
- 目标是先建立可正确运行战斗的最小权威模拟骨架，再扩展技能。
- Sim Tick 固定 **40ms（25 tps）**，逻辑与渲染严格分离。
- 顺序必须是：数据模型 → 实体生命周期 → 战斗子系统 → 技能。
- 原版 1.10f 游戏运行结果是最终真值；D2MOO、libd2、dark-magic 只提供行为和测试
  参考，不直接替代原版数值。

## P0：底层基础

### P0-1 TXT 数据表加载层（当前已完成）

对齐 1.10f MPQ 的 `stats/ItemStatCost`、`states`、`skills`、`missiles`、`monstats`
（以及运行时依赖的相关表），保留原生 stat 编号、Add/Base/Percent 运算语义、state
 标志位和 missile 碰撞/爆炸/穿透/跟随标志；禁止复用残缺旧解析器。使用原版 TXT
 导出进行字段、行列数和语义校验。

### P0-2 Stat/State 状态系统（约 93%，未完成）

- Unit 同时维护永久 stat（等级/装备）和临时 state stat（buff/debuff）。
- 聚合顺序固定为 `Base → Add → Percent`。
- 实现 tick 计时、到期移除、覆盖/堆叠、死亡清除和存档保留规则。
- 当前主要缺口是少量旧 scalar 写入路径及剩余具体诅咒/技能公式迁移。

### P0-3 Unit 实体和生命周期（约 90%，未完成）

统一玩家、怪物、NPC、佣兵、召唤物的 `Spawn → InsertWorld → TickUpdate → DeathEvent
→ RemoveWorld → Destroy`；死亡时清理 missile、state、owner 和 Target 引用，并补齐
不同单位类型的失败回滚、跨区域卸载验收。

### P0-4 固定 Sim Tick（约 98%，未完成）

独立于可变 `render()` delta，按固定 40ms 执行：

1. Unit state tick；
2. Missile 移动/碰撞；
3. AI、移动、攻击和技能；
4. 死亡事件及实体销毁；
5. 输出权威快照给渲染层。

当前只剩真实客户端长时间后台恢复等外部验收。

## P1：战斗基础骨架

### P1-5 Missile 投射物（约 95%，未完成）

生成、固定 tick 位移、单位/墙体碰撞、命中回调、爆炸、穿透、归属和回收；当前缺口
主要是跨房间真实地图命中和更精确的末帧多目标边界。

### P1-6 伤害、命中和死亡（约 95%，未完成）

近战使用攻击起手 tick 的位置快照和 hitbox；元素/物理伤害、抗性、命中/闪避、PvP、
吸收和死亡掉落按原版顺序处理。当前仍需补少量非 CombatSystem 环境伤害和边界样本。

### P1-7 物品最小闭环（约 60%，未完成）

物品实体、死亡掉落、地面物品、拾取、装备/背包占用和多人原子移动；TreasureClass
完整品质构造、插槽/尸体/腰带和全部派生属性仍在推进。

### P1-8 D2S 读写（约 60%，未完成）

保存 stat、active state、装备、任务等并完成加载→保存往返；当前还缺原版客户端进程
外部识别、完整 section/mask 和更多原版样本。

## P2：第一章可用闭环

- 怪物基础 AI：僵尸、Fallen、Rogue 弓箭手的搜寻、追击、近战、远程和死亡。
- NPC 对话、商店、修理、赌博、雇佣。
- 传送点、Warp、场景切换、门和箱子。
- 第一章六个任务的多人资格、奖励幂等、重连恢复和客户端表现。

当前 A1 基础地图和任务主体可运行；正在收尾 A1Q5 Countess 多人/重连，再处理 A1Q6
Andariel 和对象 `stateFlags` 表现。

## P3：技能扩展

技能移植顺序固定为：

1. 近战类；
2. 单体弹道（火球、冰弹）；
3. 光环类；
4. 诅咒类；
5. 复杂多 missile 技能（暴风雪、火墙）。

每个技能必须有固定等级、固定属性、原版 1.10f 伤害、状态持续 tick 和日志对照测试，
不能只依赖动画肉眼判断。刺客/野蛮人专项已基本完成，亚马逊约 99%，德鲁伊约 90%，
死灵法师与圣骑士的服务端技能首轮已基本闭环；法师基础单体弹道与 Static Field
`SrvDo020` 已完成首轮核对，下一项优先处理 Frost Nova，然后处理 Blaze/Fire Wall 等
持续区域状态与多人表现链。

## 工程约束

- 开发期锁定 1.10f MPQ，不混用其他版本资源。
- 不把 C/C++ 内存结构机械翻译成 Java；只复刻可观察行为算法。
- 单元测试优先，随后做无渲染 Sim、隐藏窗口和双客户端验证。
- 只移植行为算法，不分发暴雪 MPQ 资源。
- 任何完成项都必须在路线图中记录测试、commit、远程状态和下一步；未通过验收不得
  标记完成。
