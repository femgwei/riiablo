# 小旋风／龙卷风：原生路径与固定贴图方向

本阶段复用原版后台run `20261121-165203-4158d94f`，**没有启动新的原版实例、没有前台运行或新增UAC**。修复目标为风团的运动和外观选择，不做像素对齐。

结果：两个技能的客户端视觉和本地权威导弹，分别覆盖原版客户端的**221个位置／速度状态，均零差异**，合计442组比较。之前的221个动画游标策略及217个实际生产已加载年龄匹配保持通过。42项不同的相关测试分批通过；方向映射来自固定版本D2CMP静态表，**本次没有实际DCC绘制提交或GPU像素证据**。

## 路径为什么不同

原版不是按“累计浮点距离每2格随机拐一次”移动。它先按目标方向生成一串两格间隔的路径点，再按原生fp16速度逐tick前进。接近节点时吸附到节点、改算下一段速度；抵达起始节点的首次更新可以停留在出生点。旧实现没有这一步，转弯时刻也会持续漂移。

原版客户端RVA `0x29E80` 的初始化回调，使用 `PathGetFirstPointX + spreadIndex` 建立低半种子，高半为666。名字容易误导：固定版本D2Common#10175（RVA0x69DE0）读取path+0x10，当前是目标点X，而非出生点X。原版D2Game初始化器RVA0xE5E50同样使用这一getter。

本批出生格(4522,5642)、目标格(4530,5642)。小旋风三条路径分别从4530、4531、4532开始，生成25次随机节点；龙卷风从4530开始，生成37次。生成后随机种子low/high两半与四个原版单位记录逐条相同。旧Riiablo使用出生X+i，且先随机选初始速度，所以从开始就进入不同路径。

本级原生轴向每tick速度：小旋风30720、龙卷风24576；对角线分量分别21720、17376。对应速度来自 `(Vel<<8)*75/100` 及原生方向表，而非把表Vel直接当作每秒世界距离。旧回放与原版的最大投影距离误差，小旋风约11.7738格、龙卷风约4.9534格。旧JSON只保存舍入后的主机浮点位置，这一误差统计不是旧原生fp16逐位比较。

`NativeFirestormMotion.sample`中已经审计的原生charged-bolt求样路径现供Wind复用：起点cell center、两格节点、保持种子初始化输入、原生方向/速度及节点吸附。所有221条记录的位置、速度均复现，不靠逐tick录制位置硬编码。

## 客户端与命中路径

新增 `DruidWindPresentationSystem`响应SkillDo，按CltDo68/69分别创建3/1个独立客户端风团。它们拥有自己的出生时钟、原生路径、动画和固定外观，标为presentationOnly，移除Networked，不进入服务器碰撞网格。ClientEntityFactory走已有静默presentation分配入口，避免重复TravelSound或新建物理body；已热加载的资源立即恢复原生帧和方向。

匹配风团创建成功后，原服务器导弹作为伤害载体隐藏，Loader不再加载第二份DCC，Renderer也有兜底。隐藏使用transient标记，即使最后一个网络删除包晚到，也不会在风团结束后重新冒出伤害载体的贴图。没有SkillDo的恢复快照保留原有显示回退。若一个完整技能组未能全部分配视觉对象，会删除半组并保留完整权威回退，避免少画或重复画。

本地权威导弹也接入同一原生路径，避免视觉正确但伤害仍沿旧错误轨迹移动。`NativeDruidWindMotion`仅处理明确的Wind chargedBolt路径及初始化形态种子；其他charged-bolt、静止伤害测试载体仍走原逻辑。新Wind保留targetX+lane、666作为不可变路径输入，按nativeFrame求位置；旧检查点中已经推进的种子不强行重解释为初始化种子，仍沿原递增路径。没有新增Missile字段或改变检查点编码布局。

改变的是路径初始化与移动；伤害快照、击晕、碰撞/命中回调和龙卷风区域伤害频率仍由既有服务器系统处理。回归另验证原生路径上的小旋风确实造成伤害和10tick击晕，以及龙卷风区域脉冲独立于接触门限。实际原版服务端伤害、碰撞对象和随机伤害roll未在本轮采集，**不能以本地权威对齐客户端路径推导完整战斗一致**。

## 方向不是速度方向

采样中每个单位的path.direction在整个生命周期固定：三个小旋风为25、39、58，龙卷风为40；但velocity会多次折转。因此不能随每一段移动速度重新选择贴图方向。

D2Common#10457对导弹读取path方向字节。D2CMP在选择DCC时调用RVA0x11F0，以方向数量的bit索引查64项映射；四方向表位于RVA0x1A3D0，等价于 `((pathDirection+8)&63)>>4`。将记录中的25、39、58代入，静态推断的小旋风资源方向为2、2、0。龙卷风只有一方向，恒为0。64项映射逐项验证。

新视觉对象在出生时选择一个稳定的本地外观字节，经原生表映射到4个方向；DirectionResolver不再跟随速度折转，也不等待“两帧稳定”才切换。Renderer的插值角度不再覆盖该固定外观。**原版全局分配随机流未对齐**，所以不宣称每个风团随机分到的具体外观已与本次原版2、2、0完全相同。它是正确的映射和固定外观行为，不是已取得实际原版DCC方向提交证据。

## 生命周期与范围

- 视觉轨迹、年龄和50/75tick寿命独立于DCC加载；冷资源不冻结路径，也不延长生命周期。
- 重复施放各用自己的出生时钟。新风团不会让旧风团重新开始，旧风团也不提前删除新风团。
- 从已知主机场景进入无场景区域时删除视觉，不制造命中子层；该保护不等于完整原版房间/墙体碰撞重建。
- 碰撞只由权威实体处理，视觉不生成第二份伤害；实际原版墙体、房间退出、不同方向/等级和完整施法输入链仍待扩展。
- 现有本地视觉分配工厂和全局分配顺序不作为原版随机序列一致的证据；尚未证明跨不同渲染配置的战斗随机序列一致。
