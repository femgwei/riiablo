# 内存池使用说明

## C++ 中的使用方式

### 1. 分配结构体（D2_CALLOC_STRC_POOL）
```cpp
// C++ 代码
D2DrlgStrc* drlg = D2_CALLOC_STRC_POOL(pMemPool, D2DrlgStrc);
// 宏定义：D2_CALLOC_STRC_POOL(pMemPool, type) 
//        = (type*)memset(FOG_AllocPool(...), 0x00, sizeof(type))
// 已经做了类型转换，返回 (type*)
```

**Java 对应实现：**
```java
// Java 代码
D2DrlgStrc drlg = D2Pool.callocStrcPool(memPool, D2DrlgStrc.class);
// 使用泛型，直接返回正确的类型，无需强制转换
```

### 2. 分配数组（D2_CALLOC_POOL + 强制类型转换）
```cpp
// C++ 代码
pRoomTiles->pFloorTiles = (D2DrlgTileDataStrc*)D2_CALLOC_POOL(
    pMemPool, 
    sizeof(D2DrlgTileDataStrc) * pRoomTiles->nFloors
);
// D2_CALLOC_POOL 返回 void*，需要手动强制转换为目标类型
```

**Java 对应实现：**
```java
// Java 代码 - 方式1：使用 callocArrayPool（推荐）
roomTiles.setPFloorTiles(
    D2Pool.callocArrayPool(memPool, D2DrlgTileDataStrc.class, nFloors)
);

// Java 代码 - 方式2：使用 callocIntArrayPool（对于基本类型数组）
int[] rowOffsets = D2Pool.callocIntArrayPool(memPool, height);

// Java 代码 - 方式3：使用 callocPool（返回 byte[]，需要手动处理）
// 不推荐，因为需要手动处理类型转换
```

### 3. 分配基本类型数组
```cpp
// C++ 代码
int* pRowOffsets = (int*)D2_CALLOC_POOL(pMemPool, sizeof(int) * height);
```

**Java 对应实现：**
```java
// Java 代码
int[] rowOffsets = D2Pool.callocIntArrayPool(memPool, height);
```

## 关键区别

### C++ 的特点
- `D2_CALLOC_POOL` 返回 `void*`（无类型指针）
- 可以通过强制类型转换 `(Type*)` 转换为任何类型
- 内存是连续的，可以直接通过指针访问

### Java 的限制
- **没有指针，无法进行强制类型转换**
- 必须使用类型安全的方式分配
- 数组是对象，有类型信息

## Java 实现方案

### 方案1：类型安全的分配方法（当前实现）
```java
// 结构体分配
D2DrlgStrc drlg = D2Pool.callocStrcPool(memPool, D2DrlgStrc.class);

// 对象数组分配
D2DrlgTileDataStrc[] tiles = D2Pool.callocArrayPool(
    memPool, D2DrlgTileDataStrc.class, count
);

// 基本类型数组分配
int[] flags = D2Pool.callocIntArrayPool(memPool, length);
byte[] data = D2Pool.callocPool(memPool, size);  // 返回 byte[]
```

### 方案2：使用 ByteBuffer（如果需要真正的内存池）
```java
// 分配直接内存
ByteBuffer buffer = ByteBuffer.allocateDirect(size);
// 可以通过 slice() 创建视图，但需要手动管理类型
```

## 当前实现的状态

✅ **API 已实现（模拟，非真内存池）：**
- `callocStrcPool()` - 结构体分配，类型安全
- `callocArrayPool()` - 对象数组分配，类型安全
- `callocIntArrayPool()` - int 数组分配
- `callocPool()` - 字节数组分配

⚠️ **说明：Java/GC 无法实现真内存池**
- C++ 的真内存池：预分配一大块连续内存，从中切出多段交给调用方，显式归还后复用同一块地址；生命周期完全手动控制。
- Java 有 GC，无指针，无法“把某段地址还回池子再切给别人”；每次 `new` 都是独立对象，由 GC 管理。因此**无法实现 C++ 那种真内存池**。
- 当前实现：保留与 C++ 一致的调用方式（`D2Pool.callocStrcPool` 等），但底层每次分配仍是 `new`，仅做 API 兼容与可选追踪/统计，实际内存由 GC 负责。这不是“假”的 API，而是**语义上的模拟**（真池子做不了）。

## 移植建议

在移植 C++ 代码时：

1. **结构体分配：**
   ```cpp
   // C++
   D2DrlgStrc* drlg = D2_CALLOC_STRC_POOL(pool, D2DrlgStrc);
   ```
   ```java
   // Java
   D2DrlgStrc drlg = D2Pool.callocStrcPool(pool, D2DrlgStrc.class);
   ```

2. **数组分配：**
   ```cpp
   // C++
   D2DrlgTileDataStrc* tiles = (D2DrlgTileDataStrc*)D2_CALLOC_POOL(
       pool, sizeof(D2DrlgTileDataStrc) * count
   );
   ```
   ```java
   // Java
   D2DrlgTileDataStrc[] tiles = D2Pool.callocArrayPool(
       pool, D2DrlgTileDataStrc.class, count
   );
   ```

3. **基本类型数组：**
   ```cpp
   // C++
   int* flags = (int*)D2_CALLOC_POOL(pool, sizeof(int) * length);
   ```
   ```java
   // Java
   int[] flags = D2Pool.callocIntArrayPool(pool, length);
   ```

## 总结

Java 实现**不会出错**，因为：
1. 使用类型安全的方法，编译时检查类型
2. 泛型确保返回正确的类型
3. 不需要指针强制转换
4. 每次分配都创建新对象，由 GC 管理，这是 Java 的正常行为

当前实现是 **API 层面的模拟**：与 C++ 调用方式一致，但**不是真内存池**（GC 下无法实现）。在 Java 中这是合理取舍，类型安全且行为正确。
